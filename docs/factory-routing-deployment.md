# PDA 两厂运行配置

`pdaserver` 使用同一个 JAR 部署到 TS、SZ。启动时必须且只会激活一个厂区配置，数据库连接池创建后不会动态切库。

## 推荐启动方式

生产环境建议在服务启动脚本中固定厂区，避免多网卡、VPN 或临时路由影响判断。若服务器只检测到另一厂网段，即使设置了 `FACTORY_CODE` 也会拒绝启动；显式配置仅用于确认本厂或处理同时存在多块网卡的情况。

```powershell
# TS 服务器
$env:FACTORY_CODE = 'TS'
java -jar jcd-mes-pda-server.jar

# SZ 服务器
$env:FACTORY_CODE = 'SZ'
java -jar jcd-mes-pda-server.jar
```

未设置 `FACTORY_CODE` 时，程序才会检查服务器本机 IPv4：`10.10.*` 识别为 TS，`192.168.10.*` 识别为 SZ。同时命中两厂或无法识别时拒绝启动，不会默认连接另一厂数据库。

启动时还会交叉校验厂区代码、逻辑库名、JDBC 服务名及 PDA/WCF 地址网段。部署目录中的旧 `config/application.properties` 或环境变量若仍覆盖 `spring.datasource.url`、`wcf.material-ser.url`，且指向另一厂，服务会拒绝启动；上线前应移除这些旧路由项，只保留非厂区公共配置。

## 启动后核验

```text
GET http://<PDA后台地址>:9900/api/system/factory
```

响应只包含厂区代码、逻辑数据库名及 PDA/WCF 服务地址，不包含数据库账号、密码或 JDBC 地址。部署后至少核对：

- TS 返回 `factoryCode=TS`、`databaseName=TSMES`。
- SZ 返回 `factoryCode=SZ`、`databaseName=SZMES`。
- 后端日志中的 MaterialSer 地址属于当前厂区。

## 客户端路由

新版 APK 根据 PDA 当前网段选择业务入口，并调用上述身份接口二次核验。识别冲突、核验不可达、数据库身份不一致或后端身份不一致时停止业务请求，不尝试跨厂连接。

当前首批路由矩阵：

| 服务 | TS | SZ | 备注 |
| --- | --- | --- | --- |
| PDA Java 后台 | `10.10.100.137:9900` | `192.168.10.30:9900` | 两边均部署同一 JAR |
| Oracle | `10.10.100.121:1521/tsmes` | `192.168.10.11:1521/szmes` | SZ 地址来自原项目旧配置，上线前需现场确认 |
| MaterialSer WCF | `10.10.100.138:8021` | `192.168.10.30:8021` | APP 直连，pdaserver 也使用 |
| PRPSer WCF | `10.10.100.138:8041` | `192.168.10.30:8041` | `MES_JCD_PDA` 使用 |
| 智能货架 | `10.10.100.137:7900` | `192.168.10.30:7900` | SZ 服务尚待部署确认 |
| 发布中心 | `10.10.100.150:9911` | 共用同一地址 | 必须确认 SZ PDA 网段可路由访问 |

智能货架 `7900` 是独立服务，不属于 `pdaserver:9900`。SZ 使用 WMS 货架功能前，仍需确认 `192.168.10.30:7900` 已部署并配置 SZ 数据库、WCF 和货架硬件；不可回退到 TS 的 `7900`。

本批未迁移的固定地址仍包括 `qa.smb.root=\\10.10.100.21\物理实验室报告`，以及 LQC/旧登录更新接口中的 `10.10.100.208:9999`。在拿到 SZ 对应地址或确认两厂可共享前，保持原行为，不做跨厂猜测或回退。

本批客户端范围是 Android `APP-PLUS` APK。WMS/MES 的 H5 开发代理仍保留 TS 地址，不作为 SZ 生产入口。
